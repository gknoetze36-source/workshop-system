## What was actually wrong (all in the tests, not the app)

**58 failures across 16 files — `locations.owner_id NOT NULL` violation.**
Each file constructed a bare `Location(name="Workshop")` with no owner. That
was valid before the owner/location model existed; it's now invalid because
`Location.owner_id` is correctly required — a location with no owner is
exactly the state the "1 owner = 1 location, no orphans" rule exists to
prevent. This wasn't one shared broken fixture, so it took a per-file fix:
every `Location(name=...)` became `Location(owner=Owner(), name=...)`
(`Owner()` needs no arguments — every field but `active` is nullable, and
`active` defaults to `True`), plus adding `Owner` to each file's
`from models.core import ...` line. Files touched:

**1 failure — `tests/unit/test_flyer_lady.py::test_facebook_feed_calls_publish`.**
`flyer_lady/link_service.py`'s `_public_base_url()` correctly raises unless
it's inside a Flask request context or `PHANTA_PUBLIC_BASE_URL` is set —
that's deliberate production behavior, not a bug, so the source wasn't
touched. The test called the publisher directly with neither. Fixed with
`monkeypatch.setenv("PHANTA_PUBLIC_BASE_URL", ...)` in the test itself.

**1 failure — `tests/unit/test_platform_admin_security.py::test_production_container_runs_migrations_before_web`.**
This was a false negative: it asserted the literal string `"alembic upgrade
head"` appears in `Dockerfile`. It doesn't, because migrations actually run
through Railway's `preDeployCommand` (`railway.toml` → `database/predeploy.py`
→ `initialize_database(run_migrations=True)` → `run_alembic_migrations()`),
which completes before the Dockerfile's `CMD` (the web process) ever starts.
Rewrote the assertion to check the real mechanism — that `railway.toml`
wires `preDeployCommand` to `database.predeploy`, that `predeploy.py` calls
`initialize_database`, and that `initialize_database` calls
`run_alembic_migrations` — instead of grepping the wrong file for a step it
was never responsible for. The underlying invariant it's protecting
(migrations must complete before the web process can serve traffic) is real
and still correctly guarded; it's now checking where that guarantee actually
lives.
